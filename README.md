# Warframe — арсенал недругів

Перша робоча версія довідника у погодженому напрямі Eagle. Статичний інтерфейс призначений для **GitHub Pages**. Спільне збереження й вхід обслуговує окремий **Cloudflare Worker + D1**. Це один сайт для користувача, але два технічні компоненти.

## Що працює

- 51 зброя: 21 Kuva, 16 Tenet, 14 Coda; 66 родоначальників і 34 довідкові записи.
- Сітка / список, пошук трьома мовами, фільтри, сім типів шкоди, пояснення, джерела й білди.
- Український, англійський і російський інтерфейс; мова вибирається списком і запам'ятовується. Російською перекладено 51 зброю, 66 родоначальників, 34 поради й матрицю стихій. Усі117 назв звірено з російською Warframe Wiki; посилання на сторінки є в `public/RUSSIAN-NAMES-SOURCES.json`. Англійські переклади авторських приміток можна додати в редакторі.
- Редагування назв, стихій, матриці, описів, посилань і зображень; додавання, архівування, повернення.
- Російські поля редагуються окремо. Матриця в російському режимі зберігається в `matrix_ru`, українська — у `matrix`. Українські та англійські дані не перезаписуються перекладом.
- Історія версій, відновлення з підтвердженням, JSON-копія, одиночна та пакетна перевірка HTTP.
- Щотижневі серверні знімки після розгортання Worker; зберігаються 12 останніх. Вони в тій самій D1, тому окрему завантажену JSON-копію варто зберігати поза сервісом.

## Локальний перегляд

Потрібен Node.js 24 або новіший. У цьому каталозі:

```sh
node dev-server.mjs
```

Відкрити http://127.0.0.1:5181/. Кнопка «Відкрити локальний редактор» відкриває тестовий режим без GitHub. Дані зберігаються у `preview.sqlite` лише на цьому комп’ютері. Сервер приймає запити лише на loopback; цей вхід **не входить** до `worker.js` чи публічного каталогу `public/`.

```sh
node --test test.mjs
node prepare-seed.mjs
```

Тести використовують SQLite-адаптер для D1; OAuth і зовнішні HTTP-відповіді в них імітовані. Окремо перевірено справжнє локальне середовище workerd+D1: імпорт, читання каталогу, відмову запису без входу, CORS і запис резервного знімка. Після розгортання перевірено справжній GitHub OAuth, режим власника, збереження та читання після перезавантаження. Початковий каталог повністю відновлено після пробної зміни (version3). На живому API запис без входу повертає401, чужий Origin403. Вхід під іншим реальним GitHub-акаунтом і робота з іншого фізичного пристрою не перевірялися.

У вбудованому браузері перевірено локальне збереження після перезавантаження, валідацію URL, створення, архів, відновлення версії, пошук і порожній результат, перемикання мов, фільтри, мобільні деталі й редактор, підтвердження незбережених змін і повернення фокуса після закриття меню.

## Публікація

За дозволом власника 21.10.2026 створено [репозиторій](https://github.com/CpPrice11/warframe-arsenal), [сайт GitHub Pages](https://cpprice11.github.io/warframe-arsenal/) і [API Cloudflare](https://warframe-arsenal-api.sashagrona14.workers.dev/api/catalog). D1 містить 51 зброю, 66 родоначальників і 34 поради. Публічний каталог, пошук, фільтри, мови, картки/список, зображення, вхід власника й збереження перевірено на постійній адресі; консоль без помилок. Секрет зберігається лише в Cloudflare. Розклад копій неділя07:00UTC прийнято; майбутнє спрацьовування не перевірене. Власник відмовився від окремого домену, залишається github.io.

Для повторного розгортання у власному акаунті:

1. Створити D1, записати її `database_id` у `wrangler.jsonc`.
2. Застосувати `schema.sql`, потім `seed.sql` через `wrangler d1 execute warframe-arsenal --remote --file ...`. Seed використовує `INSERT OR IGNORE` й не перезаписує чинний каталог.
3. Зареєструвати GitHub OAuth App з callback `https://<worker>/auth/callback`. Записати публічний `GITHUB_CLIENT_ID`, точну адресу GitHub Pages з кінцевим `/` у `FRONTEND_URL`. `OWNER_GITHUB_ID` — незмінний числовий ID власника, перевірений через підключений GitHub.
4. Зберегти `GITHUB_CLIENT_SECRET` **лише** через `wrangler secret put GITHUB_CLIENT_SECRET`. Не вставляти його в чат, `public/`, Git або конфігурацію. Worker запитує лише базову ідентичність, без доступу до репозиторіїв.
5. Розгорнути Worker, записати його HTTPS-адресу в `public/config.js` як `apiBase` без кінцевого `/`.
6. Публікувати **тільки `public/`** на GitHub Pages. Підготовлений workflow запускається вручну; перед цим у репозиторії вибрати Pages → GitHub Actions. Після зміни CSS або JS оновлювати однаковий параметр `?v=` у `index.html` та імпортах `app.js` / `i18n.js`, щоб кеш не змішував різні версії інтерфейсу.
7. Перевірити справжній вхід власника, відмову сторонньому користувачу, збереження з іншого пристрою та роботу таймера копій.

Незареєстрований відвідувач читає дані; запис перевіряється сервером за GitHub ID, а не прихованою кнопкою. Сеанси діють 8 годин, у базі зберігаються хеші токенів. Номер версії захищає від перезапису змін іншої вкладки. Форма зберігає введене після конфлікту чи помилки. Автоматична перевірка посилань не змінює авторських оцінок; 403/429 означає обмеження автоматичного запиту. Поточна жива перевірка з локального сервера отримала 403 від Overframe.

Google-таблиця й Apps Script v7.1 збережені окремо; сайт імпортує початковий каталог і **не синхронізує** правки назад у таблицю. Перевірки HTTP, історія й копії реалізовані власними інструментами сайту; встановлювати Apps Script для сайту не потрібно.

Після додавання російської локалі12тестів пройдено: повнота перекладу, відповідність117 назв джерелу, ключі/підстановки всіх локалей, російський пошук і множина, перевірка нових полів та попередні серверні сценарії. Локально в браузері перевірено RU/UK/EN, збереження вибору мови, матрицю, довідник, окреме збереження RU-полів, захист незбережених правок, меню й деталі на390px; консоль без помилок. Міграція хмарного каталогу додає тільки `_ru` з перевіркою номера версії та збереженням попереднього документа в історії.
